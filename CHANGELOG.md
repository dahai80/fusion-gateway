# Changelog

All notable changes to Fusion-Gateway are documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/),
and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).
Each release entry mirrors the GitHub Release generated by `.github/workflows/release.yml`
on tag push; this file is the maintained, human-curated counterpart.

## [Unreleased]

### Fixed (shell ext-path routing, 2026-10-21) — #256

- **Manifest-declared ext endpoints route to the self-registered upstream,
  not the static-pinned one.** Acceptance verify of fusion-mlx#1281/#1285
  hit a conflict: `web_shell.modules.fusion-mlx.upstream` pinned the engine
  (:11434) while the self-registered manifest declared the web bridge
  (:11471) — the bridge-only ext endpoints (`/api/search/models`,
  `/api/notifications`) 404'd through the gateway, breaking ⌘K search and
  the notification bell for mlx.
- New per-path override in the /shell/ proxy (#256, issue option 2 — keeps
  #232 static-wins semantics for everything else): when the request path
  matches an endpoint the manifest declares in `searchProviders`/
  `notifications` (exact or segment-boundary prefix), the proxy dials the
  dynamic registration's own upstream and injects that upstream's
  credential. Pages are never matched (SPA deep links, not API paths).
- Proxy transport cache is now keyed `<module>|<upstream>` — one module can
  dial two upstreams in one lifetime without reusing the wrong client.
- Without a dynamic registration (or with upstreams equal) behavior is
  byte-identical to before.

### Added (manifest deregistration, 2026-10-20) — #253

- **`DELETE /api/v1/shell/manifests/{id}`** — manifest deregistration, found
  missing during shell#24/#250 acceptance (cleanup required hand-editing
  `shell_manifests.json` + a restart).
- `Registry.Remove(id)` drops the dynamic registration and persists the store
  file (same post-lock save pattern as Upsert). Unknown ids are a 404
  `manifest_unknown` (not idempotent-200: the shell host distinguishes
  "already gone" from "deleted now"); config.yaml static entries are
  rejected 409 `manifest_static` — they keep rendering offline from config,
  so a 200 would be a lie. A dynamic registration shadowing a static id is
  removable; the static entry survives (offline).
- Route sits behind the same `withShellManifestAuth` gate as upsert/heartbeat
  (master key or `web_shell.admin_key`, #243).
- Built-in manifests are gateway-owned: the auto-registered `fusion-admin`
  (#216) is marked via `Registry.MarkBuiltin` and `Remove` rejects it 409
  `manifest_static` like config static entries — found during live smoke,
  where a DELETE briefly removed the admin module for the process lifetime.

### Added (manifest ext fields, 2026-10-20) — #250

- **Schema v1 manifest ext fields pass through to the shell host.** `ShellManifest`
  gains three optional fields (shell#24): `searchProviders` (⌘K cross-module
  search), `pages` (sub-page deep links), and `notifications` (notification
  poll sources). Previously a fixed struct dropped them at registration, so
  the shell-side implementation was inert end-to-end.
- Validation at registration (and store load): endpoints/page routes must be
  gateway-absolute `/...` paths (no traversal, no `#`); notification kinds are
  restricted to `approvals|runs|engine`; each ext array caps at 32 entries to
  bound the list payload. No secrets are carried in ext fields.
- JSON wire keys are camelCase (`searchProviders`/`pages`/`notifications`) to
  match the shell host's ManifestDto; config.yaml static entries use
  snake_case. Fields persist via the existing embedded-struct store shape and
  surface in `GET /api/v1/shell/manifests` automatically.
### Fixed (SPA catch-all, 2026-10-20) — #249

- **The web_shell.spa_dir catch-all no longer answers API-shaped requests
  with 200 HTML.** Found in the full-GUI sweep: a typo'd module call
  (`POST /v1/rpc`) got index.html with HTTP 200; the module then failed
  `JSON.parse('<!doctype...')` and surfaced a misleading toast — the real
  404 was invisible in the network tab.
- The index.html fallback is now reserved for browser navigations: GET/HEAD
  whose Accept header prefers text/html. Every other miss (POST/PUT/DELETE,
  Accept: application/json or `*/*`) gets a 404 with the standardized JSON
  error envelope (`{"code":"not_found",...}`) plus an INFO log with
  method/path/accept.
- Root document, assets (immutable-cache), and reserved namespaces
  (`/v1/*`, `/shell/*`, `/admin/*`, `/api/*`, `/gateway/*`) keep their exact
  previous behavior.

### Added (shell hosting, 2026-10-20) — #247

- **The gateway can now host the union-web shell SPA same-origin at its root.**
  Today's integrated form is a dev posture: the shell host runs its own vite
  dev server (:11430) proxying /shell + /admin + /api to :11432, so the
  "one entry" story needs a second process and a dev server in the loop.
  New `web_shell.spa_dir`: point it at the built fusion-web-shell
  `apps/shell` dist and the gateway serves it as the root SPA with an
  `index.html` fallback for deep links — one port, one process, cookie SSO
  same-origin (#220). Every API namespace keeps precedence via ServeMux
  longest-pattern matching (`/v1/*`, `/shell/`, `/admin/`,
  `/api/v1/shell/*`, `/health*`, `/gateway/*`); unmatched paths reach the
  SPA. Unauthenticated on purpose (the first screen is the shell login, the
  same posture as the embedded /admin/ SPA); directory listings suppressed;
  `index.html` is `no-store`, `assets/*` immutable-cached. Empty (default)
  registers nothing — dev mode stays for development; a dir without
  `index.html` logs a WARN and the gateway keeps its previous 404 behavior.

### Fixed (models API, 2026-10-20) — #245

- **/v1/models now surfaces engine metadata: `modality` + `capabilities` per entry.**
  fusion-mlx declares per-model engine metadata (modality: text/image/video/audio/draft;
  capabilities: text_generation/tool_calling/structured_output/vision/embedding) but the
  gateway ModelInfo re-encode dropped both — cowork's chat-model filter (`_is_chat_model`,
  cowork #126) was a no-op against live data and every entry, incl. FLUX.1-dev (image),
  Wan2.2-TI2V-5B (video), bge-m3 (embedding), was selectable as a "chat" model. Both
  ListModels decoders now carry the fields through verbatim; cloud catalogs without
  them stay byte-identical (omitempty).

### Fixed (security/contract, 2026-10-20) — #243

- **Shell manifest registration is now admin-plane.** `POST /api/v1/shell/manifests`
  and its heartbeat previously accepted ANY authenticated client key (privilege
  inversion), while the key downstream modules actually documented —
  `FUSION_GATEWAY_ADMIN_KEY=fg-admin-key` — was a fusion-mlx backend stub the
  auth chain never accepted, so module self-registration was dead-on-arrival.
  Now: writes require the **master key** or the designated **`web_shell.admin_key`**
  (env `FUSION_GATEWAY_ADMIN_KEY`, viper-bound; must be a static `auth.api_keys`
  entry — a mismatch logs a WARN at load). Plain client keys are rejected 403.
  Breaking change for hypothetical client-key registrants — none existed in
  practice (the documented path never worked). Gate tests added; README +
  config.example.yaml updated.

### Fixed (e2e, 2026-10-19) — #241

- **03-channels "create channel with inputs, then DELETE" flake root-caused
  and fixed.** Two latent defects: (1) the type Select was driven by
  `keyboard.type('openai')` but the Select is not search-enabled, so typing
  did nothing and Enter always picked the first option ("Fusion-MLX (Local)")
  — the test never asserted the selected type, so it silently created the
  wrong channel type; (2) fixed `waitForTimeout` sleeps + 20/page pagination
  made row-visibility asserts depend on residue and timing. Now: open
  dropdown clicked case-insensitively, selection asserted, create/delete
  confirmed via API polling, 100/page before row checks, and an afterAll
  sweep hard-deletes every `e2e-ch*` channel (channel DELETE is a hard
  delete; a failed test skips its own cleanup and its residue poisons the
  next run). Suite runs 48/48 twice consecutively; spec runs 3.6× faster.

### Fixed (admin UI, 2026-10-19)

- **Keys/Channels tables: page-size changer was a no-op.** Passing a static
  `pageSize: 20` inside the antd `pagination` prop makes it a *controlled*
  value (partial-merge pins it), so the `showSizeChanger` combobox silently
  did nothing for users. Switched to `defaultPageSize: 20` (uncontrolled) on
  both pages. Surfaced by the e2e keys suite: soft-deleted (F8) keys
  accumulate in the list by design, so a long-lived store pushes fresh keys
  past page 1 and the test's row-visibility check needs the 100/page switch
  (added to `02-keys.spec.js`).

### Fixed (regression-report follow-ups, 2026-10-19)

- **B16 closed: volcengine provider is Bearer-only.** The AK/SK HMAC branch
  was unreachable (the constructor never populated the accessKey/secretKey
  fields from any config key) and its string-to-sign (method+path+timestamp)
  matched no real Volcengine scheme — a strict server would always 401. The
  dead branch is removed; Ark /api/v3 authenticates with Bearer api_key, and
  a missing api_key logs an explicit error (C1 already refuses enabled
  backends without one).

### Removed (config simplification, audit 1019)

- **Dead config fields deleted (full stack: struct + admin API + dashboard UI)**:
  `cost.enabled` / `cost.pricing_file` / `cost.budget_alert_threshold` (the
  tracker always used the hardcoded in-memory recorder; the admin Cost page
  wrote settings nothing read), `hot_reload.versioning` +
  `hot_reload.breaker_warmup_success` (never consumed by the engine),
  `AuthKeyConfig.metadata` (stored but never read). `hot_reload.breaker_drain_timeout`
  is kept (consumed by DrainAndApply). Verified-alive keys the audit flagged
  are NOT deleted: `routing.local_priority.swap_page_rate_threshold`
  (engine P2 check) and per-key `daily_budget_limit` (budget middleware).
- **Unknown-key config validator**: `config.Load`/`Reload` now walk the yaml
  tree against the mapstructure schema and log a WARN per unknown key (viper
  silently ignored them — root cause of the "changed a key, nothing happened"
  class). Dynamic map subtrees (backends.*, web_shell.modules.*) stay opaque:
  their keys are user-defined and often contain dots, which viper treats as
  nesting separators in AllSettings() (recursing would flag artifacts like
  `backends.kimi-k2.7-code` that exist only in the flattened view).
- **config.example.yaml**: legacy `route:` section rewritten to the real
  `routing:` schema (local_priority subtree, circuit_breaker without the
  removed boolean keys); `hardware.interval/enable_iokit/enable_mlx_metrics/mlx_metrics_url`
  replaced by the real nested keys (`collect_interval`, `iokit.enabled`,
  `mlx_metrics.{enabled,url}`); `tokenizer.type` → `tokenizer.provider`;
  `observability.namespace` and the dead `cost:` section dropped;
  `context_window_fallback` example commented out with a note that map keys
  must not contain dots (viper "." = nesting separator — a pre-existing
  limitation, not new).

### Fixed (audit sweep 2026-10-19)

- **Stream replay cross-principal isolation (A1)**: buffered stream entries
  record the owning principal at open; `/v1/stream/{sid}/events` replays only
  for the same principal (403 on mismatch) and a mismatched Last-Event-ID
  cursor sid is rejected (400) instead of silently replaying from the start.
- **Admin key API no longer leaks or drops the key hash (A2)**: GET returns a
  field projection without `key_hash`; PUT merges onto the stored entry so
  re-saving a key no longer wipes the hash (which broke auth for that key).
- **Identity model peek keeps the full body (A3)**: the 1 MiB LimitReader
  truncation is gone; on read error the partial body is restored instead of
  dropped.
- **Per-key TPM limits actually enforced (A4)**: the rate limiter is wired to
  a token estimator (body peek + tokenizer count, only for keys with tpm > 0)
  and a TPM reject rolls back the RPM slot it consumed.
- **Volcengine credentials (A5/B16)**: stream cancel watcher added; a
  configured `api_key` now wins over AK/SK (the old code overwrote the
  Bearer header with a non-standard HMAC); `url.Parse` errors surface.
- **Signed-provider stream relays are cancel-aware (A6/B17)**: blocking sends
  honor ctx; upstream error bodies are capped (1 MiB read / truncated log).
- **Nil wiring + nil-config panics (A7/A8)**: router nil callbacks and a nil
  hardware collector config refuse to start loudly instead of panicking.
- **TierQueue Acquire cancels its child ctx on every return path (A9)**.
- **Key/quota store races (B1)**: KeyStore getters return copies; quota
  display-state updates go through a locked `UpdateUsage`.
- **Hot-reload snapshot races (B2)**: 5 direct `s.cfg.Config` reads
  (stream deadline, proxy body cap, managed settings, webhook receiver,
  stream resume) now go through `s.snapshot()` under cfgMu.
- **Rate limiter lastAccess race (B3)**: moved inside the key-state lock.
- **RBAC short-circuits shell-session principals (B11)**: web-shell admins
  are no longer downgraded to viewer (403 on every write).
- **Circuit breaker TOCTOU (B4)**: Record*/Trip complete under breakerMu so
  DrainAndApply cannot land records on a discarded breaker.
- **Vertex token refresh single-flighted (B5)**: refresh runs under the
  provider lock with a re-check (SA loading inlined to avoid re-lock).
- **Half-open single-probe (B6)**: `Admit()` admits exactly one probe at a
  time at the P0 local / cloud / cluster gates; failures while open refresh
  `lastFailureTime`.
- **Hot-reload no longer whitewashes breakers (B7)**: half-open reset only
  when the inherited local snapshot was open; dead warmupSuccess removed.
- **Drain waits for queued waiters (B8)**: slotQueue/tierQueue waiters count
  toward the drain loop (in-flight==0 alone no longer swaps queues out from
  under waiting requests).
- **Tier queue fast path respects waiters (B9)**: freed slots dispatch by
  tier priority instead of being grabbed by new arrivals.
- **Rerank routing model check (B10)**: the loop variable no longer shadows
  the requested model; local rerank requires the requested model present.
- **Admin PUT writers (B13)**: backend/routing PUT use atomic writes +
  explicit reload; backend PUT no longer writes a masked `****` api_key over
  the real credential; `failure_threshold: 0` is now the documented
  "disabled" opt-out (validate accepts 0, breaker runtime never trips at 0).
- **Admin users PUT merge (B14)**: masked entries keep existing users instead
  of producing an empty users map (admin lockout after restart).
- **Login attempt map bounded (B15)**: expired entries are swept past 2048.
- **Task registry cancel order (B18)**: owner check happens before the map
  delete (no delete-then-reinsert window).
- **Shutdown cancels fallback pump roots (B19)**.
- **OIDC hardening (B20)**: the `admin_token` cookie is no longer an OIDC
  token source (header only); OIDC claim-to-role mapping is opt-in via
  `rbac.trust_oidc_claims` (default off).
- **MLX metrics parsing (C9)**: exact metric-name matching, series summed
  (multi-series no longer last-wins).
- **OpenRouter swallowed errors (C13)**: marshal/request-build errors surface
  instead of panicking on a nil request.
- **Cloud in-flight stream forwarder (C17)**: ctx-aware send so a gone
  consumer cannot leak the goroutine + gauge.
- **Webhook ack JSON escaping (C22)**: event names are marshaled, not
  concatenated into the JSON body.

## [0.9.20] - 2026-09-29

### Added
- **Batch API execution restored (#173)**. `POST /v1/batches` no longer
  returns a permanent 501: a background batch worker
  (`internal/server/batch_worker.go`) drains pending submissions, executing
  each request back through the server's own mux so batch traffic traverses
  the same middleware chain (auth, rate limit, routing, cost tracking) as
  direct client calls. Up to 4 requests execute in parallel per batch;
  per-request failures are recorded as `BatchResult.Error` and counted in
  `Batch.Failed` — the batch still completes. Creation returns 501 with a
  clear message when `batch.enabled=false`.

### Tests
- **`cmd/gateway` autoStart/autoStop coverage (#174)**: disabled/nil/no-command
  no-op, healthy `WaitURL` success, timeout-still-returns-started semantics,
  stop command runs with `onlyStarted=true`, and the supervisor-active skip
  guard.

### Security
- **Env-first secret injection for the admin JWT secret (#175)**.
  `admin.jwt_secret` now binds `FG_ADMIN_JWT_SECRET` via `bindSecretEnv`
  (same treatment as `FG_MASTER_KEY`/`FG_ENCRYPTION_MASTER_KEY`), so the
  signing key can be injected by Kubernetes secretKeyRef instead of plaintext
  in config.yaml. README, README_CN, and config.example.yaml document the
  env vars and the recommendation to prefer env injection.

## [0.9.19] - 2026-09-29

### Fixed
- **Memory-leak audit remediation (#166–#172)** — results of the full
  memory-leak / dead-code / release-readiness audit:
  - #166 `cost.Tracker.keyMarkups` grows unboundedly under key churn.
    `SetKeyMarkup` with a zero/negative markup now clears the entry, and a new
    `DeleteKeyMarkup` drops it on key deletion.
  - #167 Connector registry `auditLog` trim resliced instead of copying,
    keeping the ever-growing backing array alive after millions of audit
    events. Copy-trim now releases it (same pattern as the B9/EI11 fixes).
  - #168 Cloud in-flight tracking spawned a per-request `cloud_inflight_drain`
    goroutine that raced the real stream consumer for chunks and could block
    forever. Replaced with a pump wrapper that decrements the gauge when the
    stream closes — no extra goroutine, no racing consumer.
  - #169 Realtime proxy leaked the upstream response body on a failed
    WebSocket handshake (gorilla/websocket returns a non-nil response on
    error). The body is now drained and closed per failed upgrade.
  - #170 Per-key quota maps (`usage`/`dailyUsage`/`dailyDate`) accumulated
    entries for unknown key names forever. New `PruneUnknownStale` sweeps
    unknown-key entries idle > 7 days, wired on quota load and shutdown flush.
  - #171 Bedrock SigV4 `signKeyCache` never evicted stale date scopes. Stale
    scopes are now dropped on derivation (signing keys are only valid for
    their own date). E6 test updated for the new semantics.
  - #172 The admin `cost_markup` knob wrote config that nothing read at
    runtime — billing markup was always 0. `recordAndCharge` now syncs the
    config into the tracker via `ConfigSnapshot` (hot-reload aware).

## [0.9.18] - 2026-09-05

### Added
- **Cluster admission & shared circuit-breaker client visibility (#163)**.
  Multi-node MLX clusters under concurrent client processes (e.g. several
  fusion-code instances) previously had no cluster-wide admission or shared
  breaker: each process ran its own in-process semaphore and per-process
  circuit breaker, so N processes each rediscovered a failed node and hammered
  it before backing off (thundering herd). The gateway already owned the
  per-node concurrency budget (`routing.local_priority.max_concurrent`, RR4
  hard CAS cap + `SelectNodeByModel` slot skip) and the aggregated per-node
  breaker state (RR5 per-node breakers + R8 coordinator marking a tripped node
  `selectable() == false`); the gap was client visibility. `NodeStatus` now
  exposes `routable`, `breaker_bypassed`, `max_concurrent`, and
  `breaker_state` (closed/open/half_open), surfaced both under the `cluster`
  key of `GET /v1/status` and via a new dedicated read-only
  `GET /gateway/v1/cluster/health` endpoint (fg-key auth, 404 when cluster
  disabled). Clients poll one source and route around non-routable nodes
  cluster-wide without per-process rediscovery. No inference-path change;
  cluster features remain opt-in (`cluster.enabled`, default off).

## [0.9.17] - 2026-09-03

### Added
- **Per-tenant daily quotas (#159-A)**. Each team may carry a `DailyQuotaLimit`
  (USD/day) cap enforced above the inference pool: a tenant that exhausts its
  daily budget is blocked at the `BudgetBlock` middleware (fail-closed) before
  any local slot is consumed. Quota auto-deducts at every cost-record site
  (chat, streaming, embeddings, rerank) via a single `recordAndCharge` sink,
  in both the in-memory store (date-compare rollover, no background sweep) and
  the Redis store (Lua atomic `INCRBYFLOAT` + `EXPIRE` on a dated daily key).
  The tenant `Tier` tag is carried from the credential-bound team onto the
  request `Principal`.

- **3-tier priority admission queue (#159-B)**. Opt-in `routing.tier_queue`
  (default off, `mode: local` only) admits requests by class — heavy
  (diffusion, heavy models, or a tenant tagged heavy) gets head-of-line
  dispatch so a burst of light chat cannot starve a long generation; light
  gets lowest priority; general is default. FIFO within a tier. The tenant
  `Tier` tag wins over the coarse intent heuristic. A `committed` flag closes
  the dispatch race (cancel/timeout after handoff does not steal or leak the
  slot). Hot-reload rebuilds the queue (RR6 parity).

- **Dual-master active-active load balancing (#159-C)**. Cluster `master` mode
  can now front multiple fusion-multi-node masters via `cluster.master.addresses`
  with a least-conn pool + health-check failover. Each sync call routes to the
  pooled master with the fewest in-flight requests; on error the call fails
  over to the next candidate. A failing master is circuit-cooled with
  exponential backoff (5s → 2m cap) and skipped unless no healthy peer remains
  (fail-open). The singular `cluster.master.address` remains supported
  (backward-compat; single-element pool). `config.Validate` accepts either
  field for master mode.

## [0.9.16] - 2026-09-03

### Fixed
- **Identity gRPC cross-tenant guard now active (#160)**. The gateway's local
  proto copy (`internal/identity/pb/identity.proto`) was missing field `= 6`
  (`tenant_id`) on `AuthorizeAndAcquireRequest`, so `Client.AuthorizeAndAcquire`
  never populated `TenantId`, the identity servicer's `asserted` was always
  empty, and the P2-3 cross-tenant guard never triggered — a caller asserting a
  tenant differing from the api-key's real tenant was not refused at the gRPC
  plane. Synced the proto with `fusion-identity/grpc/identity.proto` (added
  `string tenant_id = 6;`), regenerated the Go stubs (`paths=source_relative`),
  added a `tenantID string` parameter to `Client.AuthorizeAndAcquire`, and
  thread the credential-resolved tenant (`p.Team.ID`, bound upstream by
  `APIKeyAuthWithStore` via `GetTeamByKey`) — NOT a client-supplied assertion.
  The identity servicer compares it against the api-key's real tenant and
  refuses a mismatch (`MODEL_UNAUTHORIZED` → 403). New tests: middleware-level
  cross-tenant refusal (`TestIdentityAuth_CrossTenantRefused`) + client-level
  wire assertion (`TestClient_AuthorizeAndAcquire_PopulatesTenantId`).

## [0.9.15] - 2026-09-02

### Added
- **fusion-identity gRPC control-plane integration** (#157). Optional
  integration with the sibling `fusion-identity` service: an
  `AuthorizeAndAcquire` RPC on the inference hot path atomically authenticates
  + acquires a concurrency lease before fusion-mlx is reached. A new
  `internal/identity` package holds the gRPC client (long-lived channel,
  keepalive, 10ms deadline) + a self-contained consecutive-failure circuit
  breaker (open after `breaker_threshold` failures, half-open probe after
  `breaker_open_sec`, denials do not trip). `middleware.IdentityAuth` sits
  after local key auth: on allow it stamps the identity-derived tenant
  (authoritative over the local key→team binding) + the lease into the request
  context; on deny it maps the error code to HTTP
  (`INVALID_API_KEY→401`, `TENANT_DISABLED/MODULE_UNAUTHORIZED/MODEL_UNAUTHORIZED→403`,
  `CONCURRENCY_LIMIT_EXCEEDED→429`, `DAILY_QUOTA_EXCEEDED→402`,
  `RATE_LIMIT_EXCEEDED→429`); on transport/breaker failure it falls back to
  local auth (`fallback_to_local: true`) or returns 503 (strict). Lease
  lifecycle: `releaseIdentityLease` calls `ReleaseLease` + `ReportUsage`
  (async, best-effort) at request end from the `withMiddleware` finalization
  funnel, covering stream + non-stream paths. VRAM priority + KV cache-tag
  isolation: the lease `priority` + `max_allowed_tokens` are forwarded to
  fusion-mlx as `X-Fusion-Priority` + `X-Fusion-Max-Tokens` headers
  (`adapter.WithLeaseSignals` / `LeaseSignalsFromContext` / injected in
  `InjectFusionHeaders`, also carried onto the resumable-stream `liveCtx`).
  The gateway is non-invasive — the allocator and KV cache live in fusion-mlx;
  these headers are the signal contract. Admin-JWT and master-key requests
  bypass the control plane. Go stubs generated in-repo from the upstream proto
  (`internal/identity/pb`). Default off (`identity.enabled: false`); config
  validated fail-closed (enabled requires endpoint + positive numeric knobs).

## [0.9.14] - 2026-09-01

### Added
- **Server-side Ed25519 signing for managed-settings payloads** (#151).
  Enterprise fusion-code clients fetch remote policy (managed-settings) from
  the gateway; the client recomputed a checksum locally but the checksum was
  server-supplied, so a compromised/impersonating server could serve a
  consistently-poisoned payload + matching checksum. New
  `managed_settings` config block (default off): when enabled, the gateway
  signs the payload with an Ed25519 private key (`private_key`, base64 32-byte
  seed, env `FG_MANAGED_SETTINGS_PRIVATE_KEY`) and serves it at
  `GET /gateway/v1/managed-settings` with a detached signature header
  `X-Fusion-Signature: ed25519:<base64>`. The matching public key is exposed
  at `GET /gateway/v1/managed-settings/pubkey` (`{"alg":"ed25519","public_key":"<base64>"}`)
  for client pinning — clients verify the signature against a pinned key
  before trusting the payload, so a server without the private key cannot
  forge a valid payload. Payload served verbatim (not re-serialized) so the
  signature is over the exact bytes received. Fail-closed: enabled + missing/
  invalid key rejected at config load. Hot-reload rebuilds the signer for key
  rotation without restart. Behind `withMiddleware` (fg-key auth).

## [0.9.13] - 2026-09-01

### Added
- **Multi-instance fusion-mlx HA routing** (#150 Gap 2). The gateway routed
  MLX `/v1/*` to a single upstream; with multiple MLX instances
  (fusion-mlx#754) there was no load balancing or failover. New
  `cluster.ha_routing` config (default off): when enabled and a healthy
  cluster node on the mac platform (`mac_platform_tag`, default `"mac"`)
  serves the requested model, `decideLocked` routes to the cluster pool at
  P0.25 — before the single-local-upstream path — reusing
  `SelectNodeByModel` (health-weighted least-connections / hardware-aware /
  round-robin, per-node health check + per-node circuit breaker, #95/RR5/RR13).
  A non-mac node serving the model (e.g. a cuda node) is NOT a local-class HA
  peer and falls through to the normal chain. Default off: single-node
  deployments keep the unchanged single-local behavior. The CLI's

## [0.9.12] - 2026-09-01

### Added
- **Gateway-authoritative tenant identity on every proxied request** (#150
  Gap 1, gateway-side). The store already held a key→team binding

  tenant only when the api-key path did not already bind one (credential
  binding is the stronger identity). Master/legacy keys with no binding omit
  the header (single-tenant default preserved). The direct-port rejection

### Fixed
- **Local-exclusive models cloud-diverted on a full-GPU host** (#148 follow-up).

  breaker-open is a "local DOWN" signal (cloud is still the least-bad fallback
  even though it will 400), whereas the overload heuristics describe a "local
  BUSY" signal where local-exclusive has no cloud alternative anyway. Extracted
  `localExclusiveDecision` helper; two new tests pin both branches
  (`TestDecide_LocalExclusiveModel_GPUMemoryLowStaysLocal`,
  `TestDecide_LocalExclusiveModel_BreakerOpenStillCloud`). Verified live:

## [0.9.8] - 2026-09-01

### Fixed
- **`auto_start` no longer fights fusion-supervisor over the fusion-mlx
  lifecycle** (#141). fusion-supervisor (`fusion-sv`, a Rust daemon) manages
  fusion-mlx as one of its supervised services — starting it in the core layer
  on `fusion-sv up` and stopping it authoritatively on `fusion-sv down`. The
  gateway's own `server.auto_start` independently launched fusion-mlx on
  startup and stopped it on shutdown, so on a supervisor-managed host the two
  were uncoordinated: the gateway could stop a healthy mlx mid-request (or
  double-start it, racing the supervisor's probe-first recovery).
  - Fix: `supervisorActive()` detects the supervisor explicitly — `FUSION_SV_ACTIVE=1`
    env var OR the supervisor UDS socket (`/tmp/fusion-sv.sock`) present — and
    `autoStartLocal` then skips the launch, returning `started=false`.
    `autoStopLocal` takes the `started` flag and is a no-op when the gateway
    did not start the backend, AND skips when the supervisor is active (the
    supervisor owns the stop). The handoff is no longer left to the
    supervisor's probe-first heuristic; detection is explicit.
  - `auto_start` remains the standalone fallback for non-supervisor
    environments (bare gateway, single-binary, CI); on managed hosts the
    supervisor is authoritative. `config.AutoStartConfig` struct +
    `config.example.yaml` document the handoff.
  - Tests: `TestSupervisorActive_EnvGate`, `TestSupervisorActive_SocketProbe`
    (hermetic — swaps the socket path to `t.TempDir`, never touches the real
    `/tmp/fusion-sv.sock`), `TestSupervisorActive_NeitherActive`,
    `TestAutoStartLocal_SkipsWhenSupervisorActive` (sentinel command never
    runs), `TestAutoStopLocal_OnlyStarted` (no-op when not started). 35 cmd
    tests race-green; 2863 tests across 26 packages green.

## [0.9.6] - 2026-08-30

### Fixed
- **`withAdminOnly` routes returned 403 for a valid admin-login JWT** (#137/#138).
  `withAdminOnly` checked `middleware.IsAdmin` BEFORE the `withMiddleware` auth
  chain ran, and the admin module issues its own JWT (`AdminClaims{Role:"admin"}`
  via `/admin/api/login`) that the chain never parsed into `middleware.Principal`.

    `AuthMethod=="admin-jwt"` so the chain neither overwrites the bridged role
    nor 401-rejects an admin-JWT Bearer. Fail-closed: invalid/non-admin token
    leaves `Principal` untouched and `IsAdmin` denies (403); a no-op when the
    admin module is disabled. Master-key reject still fires first (plane
    separation preserved).
