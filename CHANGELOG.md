## [0.9.3] - 2026-08-30

### Fixed
- **Browser scheduling auth handshake** (issue #132). The `internal/browser/`
  `NodeClient` silently skipped the FR-10/H-5 UDS auth handshake on every node
  op, so a live fusion-browser node (which requires the first frame on a
  connection to be `{type:"auth", token}` and replies `auth_denied` + close
  otherwise) rejected all gateway traffic. Root cause: the v0.9.0 client sent
  the op frame directly with no auth, and the offline fake node did not model
  the gate, so CI stayed green while the live path was broken. The fix threads
  a per-node `token` end-to-end:
  - `internal/browser/wire.go`: added `AuthMessage{type, token}`,
    `reqTypeAuth="auth"`, `respTypeAuthAck="auth_ack"`,
    `ErrCodeAuthDenied="auth_denied"` (mirrors `Protocol.swift`).
  - `internal/browser/client.go`: `roundTrip` now sends the auth frame first
    and asserts an `auth_ack` before the op frame; a missing token fails closed
    before any dial; a `auth_denied` reply is surfaced verbatim as a
    `*NodeError` (never coerced to a generic 502 — RC1 lesson).
  - `internal/browser/registry.go` + `proxy.go`: every forward reads the node's
    `token` via `TokenOf` and passes it to the client; `RegisterDialin` carries
    the dial-in token.
  - `internal/config/config.go`: `BrowserNodeConfig.Token` field +
    fail-closed `Validate` (an empty token is rejected — a node without a
    token is deny-all, seeding one anonymous is an operator error).
  - `internal/browser/fakenode_test.go`: the fake node now enforces the auth
    gate (first frame must be `{type:"auth", token}`, else `auth_denied` +
    close), so a future regression that drops the handshake fails CI instead of
    shipping green. New `client_test.go` adds the #132 regression guards:
    correct token served, wrong token rejected with `auth_denied` (op never
    served), empty token fails closed (no dial), auth runs on every dial.
- `config.example.yaml`: `browser.nodes` example now includes the `token` field
  with a note it must match the node's `authToken` and should be an env-var
  reference rather than a literal.

## [0.9.2] - 2026-08-30

### Fixed
- Dependency security bump to clear the `govulncheck -mode=source` SCA gate:
  Go toolchain `1.26.3`→`1.26.6` (9 reachable stdlib advisories: net/url
  GO-2026-6218, html/template GO-2026-6091, crypto/tls GO-2026-6090/5856,
  net/http GO-2026-6089/5026, encoding/asn1 GO-2026-5972, net/textproto
  GO-2026-5039, crypto/x509 GO-2026-5037) and `google.golang.org/grpc`
  `v1.81.1`→`v1.82.1` (GO-2026-6061, xDS RBAC + HTTP/2). The v0.9.1 release
  binary was built on the pre-bump toolchain; v0.9.2 is the first release
  built on the patched toolchain with 0 reachable vulnerabilities.

## [0.9.1] - 2026-08-30

### Added
- Enterprise production-readiness hardening (this cycle):
  - `govulncheck` SCA gate in CI — fails on known vulnerabilities in the 56
    direct Go dependencies.
  - Release artifacts now ship a CycloneDX SBOM + `checksums.txt` (sha256) for
    verifiable provenance.
  - Grafana dashboard + Prometheus alerting rules under `deploy/observability/`,
    closing the metrics-to-alerting loop.
  - End-to-end load/stress baseline test (P99 latency, steady-state memory,
    slot-no-leak under concurrent + SSE load).
  - `internal/httpx` transport tests (0% → covered), plus connector/oauth2,
    jitter, and lifecycle Worker coverage backfills.

### Changed
- `internal/admin/ui/embed.go`: bare `panic(err)` on the unreachable embedded-
  dist subtree failure replaced with a logged 500 response — no process crash
  on a future dist/ rename.

### Fixed
- `internal/server/task_registry.go`: data race in `Register`/`Release` — three
  sites read `len(r.tasks)` after releasing the mutex, racing concurrent map
  writes. All counts now read inside the lock (E8 mutex-owns-field). Exposed by
  the new concurrent load test under `-race`; real production concurrency bug.

## [0.9.0] - 2026-08-29

### Added
- **Cross-node browser-session scheduling subsystem** (`internal/browser/`,
  issue #130, PR #131). The gateway becomes the scheduler + full proxy for the
  fusion-browser multi-node capacity plane:
  - Hybrid node discovery: static config seed (`browser.nodes`) + dial-in
    self-registration + 5s capacity poll.
  - Headroom-based placement (rank most `free_memory_mb` desc → fewest
    `live_sessions` asc → config `id` asc); global session ceiling.
  - REST ingress `/v1/browser/*` (create / execute / close / metrics / nodes);
    in-memory session→node pin map (non-persistent engine = no persisted pin).
  - Length-prefixed JSON wire protocol over UDS (4-byte big-endian prefix,
    8 MiB frame cap, 30s partial-frame timeout) — byte-exact mirror of the
    fusion-browser Swift protocol.
  - Dead-node re-route: failed-pin execute evicts the pin and returns
    `session_lost`; node errors relayed verbatim (distinct codes, not coerced
    to 502).
  - Default-off via `browser.enabled`; full `browser.*` config namespace.
  - 59 offline fake-UDS tests (pass with `-race`).
- Recovery runbook (`docs/runbook-recovery.md`) with RPO/RTO table and
  backup/restore procedures.

## [0.8.38] - 2026-08-26

### Changed
- Cloud fallback + MCP gateway migrated into the gateway (issue #87). Gap
  `max_cost_per_day` = `daily_budget_limit` closed.

### Fixed
- `/v1/chat/completions` failure surfaces upstream error detail via
  `writeChatFailedError`, capped 512 bytes (#104).
- fusion-mlx slot-leak double-decrement: `Cancel` double-released
  `inFlightCounter` → underflow → P5 bypass; `Cancel` now no-op, sole
  release via `defer` (v0.8.40).
- Per-node circuit breaker (RR5): `nodeBreakers` keyed by nodeID isolates a
  failing node; the shared breaker no longer poisons the whole cluster.
- Agent slot scheduler (ADR-001, #102): per-node cap in
  `SelectNodeByModel`, opt-in `slotQueue`, `POST /v1/agent/tasks/{id}/cancel`.
